# 資格與抽獎規則

原始留言、資格判定、籤池與抽獎快照分開保存，以作者 ID 識別參加者。顯示名稱不是身分識別；同一帳號更名仍共用籤數。留言與回覆以留言 ID 去重，所有層級共用規則。

## 資格

- 指定文字：`String.includes` 字面包含，保留大小寫與標點，不當作正規表達式。
- Tag：從本文的 `@username` 解析，支援英數、底線與帳號內的句點；不解析電子郵件及 URL 的 `@`。Tag 名稱不分大小寫，同則重複只計一次，排除該則留言作者自己的帳號。
- 截止：台北輸入轉為 UTC 保存；`留言時間 <= 截止時間` 視為符合。未設定則不限。
- 資料識別與時間若不合法，停止擷取或排除資格，不猜測缺少的作者資訊。

## 籤數

按時間由早到晚，再以留言 ID 的字串序比較同時間留言。取得順序不影響計算。

「每人一次機會」為預設，同一作者至少一則留言合格，取得一張籤；後續合格留言標示資格合格，但不增加籤數。

「Tag 新朋友增加機會」中，N 最低為 1。每則合格留言需至少 N 位尚未替該作者計入籤數的朋友才得一張籤。成功時全部有效 Tag 都記為已使用；未成功或未符合資格時不消耗 Tag。其他作者使用過同一位朋友，不影響本作者。

N = 2 範例：

| 留言  | 尚未使用的朋友 | 新增籤数 | 累計 |
| ----- | -------------- | -------- | ---- |
| @A @B | A、B           | 1        | 1    |
| @A @C | C              | 0        | 1    |
| @C @D | C、D           | 1        | 2    |

## 抽獎

獎項名稱不可空白，数量必須為正整數。依畫面排序逐獎項、逐名額抽取。

每次從剩餘籤中等機率選一張。`crypto.getRandomValues(Uint32Array)` 產生 32 位整數；拒絕超出最大可整除區間的值，再取模，避免取模偏差。沒有固定種子。

預設抽中某作者後移除該作者的全部籤，因此剩餘帳號依仍持有的籤數加權。允許同帳號多次中獎時只移除中獎籤；每張籤至多得獎一次。名額不足以剩餘帳號或籤數計算，抽獎前完整檢查。

每次保存紀錄 ID、台北可顯示的 UTC 時間、貼文、規則、獎項、原始留言、資格判定、籤池、得獎結果及亂數演算法版本。既有紀錄不因規則更改或重抽而更新。本機紀錄供回查，不是第三方公證或防竄改證明。
